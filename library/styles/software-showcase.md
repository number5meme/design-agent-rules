# Software Showcase Design Method

Organize content by the capabilities, value, and usage process users need to understand; light/dark, color, and visual density are decided by the brand and materials.

## Expression and Structure

- Capabilities can be explained with product interfaces, flows, comparisons, demos, or narrative; choose each section's structure by content, not fixed to heading, description, and screenshot.
- When showing real interfaces, the actions and data should support the stated capabilities; complex areas can be zoomed in locally; do not use unreadable screenshots merely as decoration.
- Express action hierarchy through position, copy, shape, and color together; the primary action is not required to use a particular accent color.
- Surfaces and grouping support content relationships; when an existing text-and-image structure is clear, no extra card wrapper is needed.

## Visuals and Adaptation

Choose typefaces by expression and usability; correct letter spacing by actual language and typeface. When using dark, verify text, focus, and necessary borders per [Color Pairing](../../standards/defaults.md#color-pairing).

Re-layout content for target widths; crop screenshots when necessary or provide a zoom entry, without hiding key results. Check heading wrapping, screenshot text, button states, and readability of weak text. Showcase page style does not automatically decide in-app theme, navigation, and density.
